# NASA Datasets & Data Sources for LUNA-SAFE 2.0

> **Purpose:** A curated catalogue of NASA data services and lunar science datasets that can support LUNA-SAFE 2.0's lunar imagery, terrain analysis, hazard assessment, rover route planning, and mission-context features.
>
> **Reviewed:** 22 November 2026  
> **Project:** LUNA-SAFE 2.0 – AI-Powered Lunar Terrain Intelligence and Autonomous Rover Navigation System

---

## 1. Important distinction: integrated APIs vs. downloadable science data

LUNA-SAFE uses different kinds of NASA resources. They are not interchangeable.

- **Live API integrations** return JSON metadata, imagery references, or space-weather notifications. They are already called by the current backend.
- **Lunar science archives** contain actual elevation, camera, thermal, radar, composition, and instrument data. Most must be located, downloaded, processed, and imported separately.
- **Synthetic terrain** is generated by LUNA-SAFE for its offline demonstration. It is not NASA data and must always remain labelled as simulated.

### Current integration status

| NASA source | What LUNA-SAFE currently does | Status | Can it provide a lunar DEM? |
|---|---|---|---|
| NASA APOD Basic | Retrieves the Astronomy Picture of the Day and attribution metadata for the NASA imagery panel | Integrated | No |
| NASA Image and Video Library API | Searches NASA media for Moon/lunar images and displays archive thumbnails and metadata | Integrated | No; archive imagery is not automatically georeferenced |
| NASA DONKI Notifications | Displays recent space-weather notifications as mission context | Integrated | No |
| LOLA PDS archive | Not automatically downloaded; candidate source for real elevation grids | External dataset; manual import workflow | Yes, selected GDR products |
| SLDEM2015 | Not bundled or automatically imported; recommended high-resolution DEM source | External dataset; manual import workflow | Yes |
| LROC PDS archive | Not automatically downloaded; candidate source for camera imagery and local DTMs | External dataset; manual import workflow | Yes, where DTM products exist |
| Diviner, LEND, Mini-RF, GRAIL, CRaTER, LAMP, SPICE, M3, LCROSS and Lunar Prospector | Documented below as optional context/science layers; not currently used by route calculations | Not integrated | Mostly no; see individual sections |

**Do not describe APOD, DONKI, or an ordinary NASA image search result as actual lunar surface elevation.** The live API integrations do not currently feed the A* route planner. The planner operates on the currently selected terrain grid, which is synthetic by default or user-imported from a supported CSV file.

## 2. Live NASA services already used by the backend

### 2.1 NASA Astronomy Picture of the Day (APOD Basic)

- **Endpoint:** `https://science.nasa.gov/wp-json/wp/v2/apod-basic`
- **Use in LUNA-SAFE:** NASA Data Centre and latest imagery panel.
- **Returned information:** APOD content and associated metadata such as title, date, explanation, image/media URL and available credit information.
- **Limitations:** APOD is general astronomy content. An item may show a galaxy, nebula, planet, or other subject instead of the Moon. Even a lunar image is not necessarily georeferenced, orthorectified, or suitable for slope calculation.
- **Authentication:** The project backend uses the configured NASA API key setting for this request. Keep the key on the server; do not place it in frontend code.
- **Official reference:** [NASA Open APIs – APOD update and endpoint](https://api.nasa.gov/)

NASA's API portal announced that APOD moved to the APOD Basic WordPress endpoint on 10 September 2026 and that the legacy `/planetary/apod` endpoint is scheduled to be archived on 1 December 2026. LUNA-SAFE is configured to use the newer endpoint.

Example request:

```bash
curl "https://science.nasa.gov/wp-json/wp/v2/apod-basic"
```

A date may be requested with the `date=YYYY-MM-DD` parameter, as documented by NASA.

### 2.2 NASA Image and Video Library API

- **Base URL:** `https://images-api.nasa.gov`
- **Search endpoint:** `GET /search`
- **Use in LUNA-SAFE:** Search for lunar/Moon media to support the imagery browser and NASA Data Centre.
- **Example used by the project:**

```bash
curl "https://images-api.nasa.gov/search?q=Moon%20lunar%20surface&media_type=image&page_size=8"
```

- **Useful response fields:** `collection.items[].data[0]` contains item metadata, including the NASA asset ID, title, description, date and centre where supplied. `collection.items[].links[]` may contain a preview image. Use the asset ID to retrieve the media manifest through `/asset/{nasa_id}`.
- **Authentication:** The Image and Video Library API search is not configured with the NASA API key in this project.
- **Limitations:** The API is a media catalogue, not a digital elevation model service. Search results may include press imagery, illustrations, artist concepts, spacecraft images, or images without map coordinates. Do not use a thumbnail as a height map or treat its pixels as geographic coordinates.
- **Official references:** [NASA Image and Video Library](https://images.nasa.gov/) · [NASA API documentation PDF](https://images.nasa.gov/docs/images.nasa.gov_api_docs.pdf) · [NASA Open APIs](https://api.nasa.gov/)

### 2.3 NASA DONKI – Space Weather Database Of Notifications, Knowledge, Information

- **Endpoint:** `https://api.nasa.gov/DONKI/notifications`
- **Use in LUNA-SAFE:** Show recent notifications and event summaries in the NASA Data Centre / mission-context panels.
- **Example request:**

```bash
curl "https://api.nasa.gov/DONKI/notifications?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&type=all&api_key=YOUR_NASA_API_KEY"
```

- **Mission relevance:** Space-weather information may inform radiation, communications, and operational planning at a mission level.
- **Limitations:** DONKI does not measure local lunar topography, crater geometry, boulders, or surface slope. It is deliberately excluded from local terrain risk scores and A* route costs in the current application.
- **Authentication:** Use a NASA API key stored in the backend `.env` file.
- **Official reference:** [NASA Open APIs – DONKI](https://api.nasa.gov/)

## 3. Primary lunar terrain and elevation datasets

These are the most relevant sources for replacing the synthetic demonstration terrain with real lunar topography.

### 3.1 Lunar Orbiter Laser Altimeter (LOLA) – Lunar Reconnaissance Orbiter (LRO)

- **Instrument:** LOLA – Lunar Orbiter Laser Altimeter.
- **Archive:** [PDS Geosciences Node – LOLA](https://pds-geosciences.wustl.edu/missions/lro/lola.htm)
- **Most recent data discovery:** [LOLA Data Node](https://imbrium.mit.edu/) and [Lunar Orbital Data Explorer (ODE)](https://ode.rsl.wustl.edu/moon/)
- **What it measures:** Laser-altimeter observations used to determine lunar surface topography.

Relevant product families:

| Product family | Meaning | Possible LUNA-SAFE use |
|---|---|---|
| EDR – Experiment Data Records | Raw instrument observations | Reprocessing and instrument-level science; not the easiest direct DEM input |
| RDR – Reduced Data Records | Processed/geolocated elevation profiles | Build or validate regional elevation grids |
| GDR – Gridded Data Records | Gridded lunar topography / digital elevation products | **Primary candidate for global or regional elevation input** |
| RADR – Radiometry Data Records | LOLA radiometry/albedo-related products | Surface-property context; not a substitute for elevation |
| SHADR – Spherical Harmonic Data Records | Spherical-harmonic gravity/topography-related representations as defined by the product documentation | Geophysical analysis; not a simple local raster DEM |

The PDS Geosciences Node provides PDS4 bundles and documentation for LOLA product families. The LOLA Data Node also provides data, labels, documentation and software. Its higher-level GDR maps include global and polar map products at different resolutions.

**Recommended use:** Start with an appropriate LOLA GDR for the selected region. Use the matching product label and Software Interface Specification (SIS) to confirm map projection, pixel spacing, sample type, elevation reference, scale/offset, and no-data values before processing.

**Important:** Do not assume that every LOLA product file is a ready-to-use GeoTIFF. Some products use PDS image formats, detached labels, or GeoJPEG2000. Read the product documentation before conversion.

### 3.2 SLDEM2015 – High-resolution Lunar Topography

- **Product:** SLDEM2015 – SELENE/LRO Digital Elevation Model.
- **Composition:** A combined lunar shape model using LOLA altimetry and the SELENE/Kaguya Terrain Camera stereo data.
- **NASA product page:** [NASA Goddard Planetary Geology, Geophysics and Geochemistry Laboratory – SLDEM2015](https://pgda.gsfc.nasa.gov/products/54)
- **Download archive:** [LOLA Data Node – SLDEM2015](https://imbrium.mit.edu/DATA/SLDEM2015/)
- **Scientific reference:** Barker et al., “A new lunar digital elevation model from the Lunar Orbiter Laser Altimeter and SELENE Terrain Camera,” *Icarus*, Volume 273, pages 346–355 (2016). [DOI: 10.1016/j.icarus.2015.07.039](https://doi.org/10.1016/j.icarus.2015.07.039)

Available forms listed by NASA include:

- Global maps for latitudes between 60° South and 60° North.
- Global FLOAT IMG maps at 128 and 256 pixels per degree.
- Global JPEG2000 maps at 128, 256 and 512 pixels per degree.
- Regional tiles in FLOAT IMG and JPEG2000 formats at the resolutions listed on the NASA product page.

**Recommended use:** SLDEM2015 is a strong first candidate for a real-DEM demonstration over a region covered by the product. It can support elevation, slope, local relief and terrain-derived roughness calculations after correct decoding and geospatial alignment.

**Coverage warning:** The global maps described on the NASA product page cover 60°S to 60°N. Do not assume that this global product provides uniform coverage of the polar regions. For polar missions, inspect LOLA polar GDR products and relevant LROC polar products.

**Citation requirement:** Cite the Barker et al. paper and the data archive/product used when SLDEM2015 contributes to a result.

### 3.3 Lunar Reconnaissance Orbiter Camera (LROC)

- **Instrument:** LROC – Lunar Reconnaissance Orbiter Camera, including the Narrow Angle Camera (NAC) and Wide Angle Camera (WAC).
- **Archive:** [LROC PDS Data Node](https://pds.lroc.im-ldi.com/data)
- **Mission data guide:** [PDS Geosciences Node – LRO](https://pds-geosciences.wustl.edu/missions/lro/default.htm)
- **Browse tools:** [LROC QuickMap](https://quickmap.lroc.asu.edu/) and [NASA Moon Trek](https://trek.nasa.gov/moon/)

Relevant products include:

| LROC product | What it contains | Possible LUNA-SAFE use |
|---|---|---|
| NAC EDR/CDR images | Narrow-angle camera raw/calibrated image products | High-detail visual inspection of local terrain, crater rims and visible boulder fields |
| NAC DTM products | Local digital terrain models derived from stereo imagery | Higher-resolution local elevation and slope where a DTM exists |
| NAC ROI / polar mosaics | Region-of-interest and polar image mosaics | Detailed imagery context for a selected landing or traversal area |
| WAC global morphology mosaics | Broad-coverage lunar image mosaics | Regional context and visual basemap |
| WAC DTM products | Wide-angle camera-derived terrain products where available | Broader-scale elevation context |
| WAC colour and regional mosaics | Colour/compositional and regional imagery products | Visual and scientific context, not automatically a DEM |

**Recommended use:** Pair LOLA or SLDEM2015 for broad-scale elevation with a matching LROC NAC DTM for local detail where coverage permits. Use NAC/WAC imagery to review a terrain interpretation, but do not claim that image-only boulder detections are ground-truth without suitable validation.

**Coverage warning:** LROC NAC coverage is not a single uniform, global high-resolution DTM. Search the archive for the region and product type you need. Products and release contents change over time.

### 3.4 NASA Moon Trek

- **Portal:** [NASA Moon Trek](https://trek.nasa.gov/moon/)
- **Purpose:** Interactive lunar mapping and mission-planning exploration portal.
- **Useful capabilities/layers shown by the portal:** LRO WAC mosaics, NAC imagery search, elevation profiles, slope, surface lighting, crater/rock detection tools and other lunar map layers.
- **Use in LUNA-SAFE:** Discover candidate data layers, inspect an area, compare the selected DEM/imagery, and identify a dataset or map product for later import.
- **Access note:** The portal states that basic data and functionality are publicly available; certain advanced tools for mission planning and research may require an approved registered account.
- **Limitation:** Moon Trek is a web mapping and analysis portal, not an API endpoint currently integrated into LUNA-SAFE. Do not invent tile-service URLs. Use its official download or data access options and respect the layer's product documentation.

## 4. Supporting LRO datasets (useful, but not DEM replacements)

These datasets can add context to mission planning. They should not be converted into a terrain elevation grid unless the product documentation explicitly defines them as elevation.

### 4.1 Diviner Lunar Radiometer Experiment (DLRE)

- **Archive:** [PDS Geosciences Node – Diviner](https://pds-geosciences.wustl.edu/missions/lro/diviner.htm)
- **Measures:** Lunar surface thermal emission and reflected solar radiation using multiple channels. The PDS instrument page describes surface-temperature mapping at roughly 500-metre horizontal scales.
- **Potential use:** Thermal environment, temperature extremes, illumination/thermal modelling, and science context for route or landing-site assessment.
- **Not suitable for:** Direct slope calculation, elevation reconstruction, or automatic boulder detection.
- **Caution:** Thermal conditions depend on local time, illumination, season/latitude and the specific derived product. A thermal anomaly is not automatically a physical traversal obstacle.

### 4.2 Lunar Exploration Neutron Detector (LEND)

- **Archive:** [PDS Geosciences Node – LEND](https://pds-geosciences.wustl.edu/missions/lro/lend.htm)
- **Measures:** Neutron flux from the lunar surface; derived products can support analysis of hydrogen abundance and polar volatile context.
- **Potential use:** Broad-scale resource and polar-region science context, especially when evaluating areas of interest around permanently shadowed regions.
- **Not suitable for:** Local surface elevation or cell-by-cell obstacle masks.
- **Caution:** Neutron measurements have a footprint and require scientific interpretation. Do not treat a hydrogen proxy as a direct map of exposed water ice or a rover hazard classification.

### 4.3 Mini-RF – Miniature Radio Frequency technology demonstration

- **Archive:** [PDS Geosciences Node – LRO Mini-RF](https://pds-geosciences.wustl.edu/missions/lro/mrf.htm)
- **Measures:** Lunar radar observations and derived radar products. The archive includes raw, calibrated, map-projected, mosaic and newer bistatic radar product collections.
- **Potential use:** Radar scattering, dielectric-property and roughness-related research; additional context for selected polar regions and subsurface/volatile investigations.
- **Not suitable for:** Direct elevation or confirmed boulder detection without an appropriate processing and interpretation model.
- **Caution:** Radar signatures can have multiple physical explanations. Do not label a radar-bright/dark pixel as ice or a hazard without supporting evidence.

### 4.4 CRaTER – Cosmic Ray Telescope for the Effects of Radiation

- **Archive:** [NASA PDS/PPI – LRO CRaTER](https://pds-ppi.igpp.ucla.edu/mission/LUNAR_RECONNAISSANCE_ORBITER)
- **Measures:** Radiation environment and particle energy information relevant to the lunar orbital environment.
- **Potential use:** Crew/rover electronics radiation exposure context and mission-level operational assessment.
- **Not suitable for:** Local terrain mapping or route geometry.

### 4.5 LAMP – Lyman-Alpha Mapping Project

- **Archive discovery:** [PDS Geosciences Node – LRO mission instruments](https://pds-geosciences.wustl.edu/missions/lro/default.htm) · [NASA PDS LAMP GDR](https://pds.nasa.gov/ds-view/pds/viewDataset.jsp?dsid=LRO-L-LAMP-5-GDR-V1.0)
- **Measures:** Far-ultraviolet observations of the lunar surface and permanently shadowed regions; the instrument observes reflected far-UV light including Lyman-alpha sky-glow and UV starlight.
- **Potential use:** Surface reflectance and polar volatile/illumination science context, depending on the selected product. LAMP maps are science layers, not surface elevation.
- **Not suitable for:** Direct topographic hazard mapping.
- **Note:** Consult the LAMP product labels and Planetary Image Atlas before choosing a particular collection for analysis.

### 4.6 LRO SPICE kernels

- **Archive:** [NASA NAIF SPICE](https://naif.jpl.nasa.gov/naif/data.html) and the [PDS LRO mission page](https://pds-geosciences.wustl.edu/missions/lro/default.htm)
- **Contains:** Spacecraft and instrument geometry, ephemerides, orientation and timing information in SPICE kernel formats.
- **Potential use:** Coordinate transformations, observation geometry, illumination/time calculations and aligning observations with a common reference frame.
- **Not suitable for:** A DEM or imagery by itself.
- **Integration status:** Not currently loaded by the LUNA-SAFE application.

## 5. Other NASA or NASA-archived lunar mission datasets

These sources can supplement LRO products when the selected area or science question warrants them.

### 5.1 GRAIL – Gravity Recovery and Interior Laboratory

- **Archive:** [PDS Geosciences Node – GRAIL](https://pds-geosciences.wustl.edu/missions/grail/)
- **Data:** Gravity and radio-science products, including derived lunar gravity-field models.
- **Potential use:** Regional geophysical context, lunar interior and mass-distribution research, and selected gravity-model studies.
- **Not suitable for:** Local rover-scale elevation, crater-edge detection or a direct traversability mask. Gravity-field resolution and terrain elevation are different measurements.

### 5.2 Moon Mineralogy Mapper (M³) – Chandrayaan-1

- **Instrument:** NASA's Moon Mineralogy Mapper carried on the ISRO Chandrayaan-1 orbiter.
- **PDS archive:** [NASA PDS M³ Bundle](https://pds.nasa.gov/ds-view/pds/viewBundle.jsp?identifier=urn%3Anasa%3Apds%3Ach1_m3)
- **Data:** Hyperspectral observations and derived radiance/reflectance products from the lunar surface.
- **Potential use:** Mineralogical and hydration-related science context for landing-site selection or resource studies.
- **Not suitable for:** Direct elevation, slope or obstacle maps.
- **Note:** This is a NASA instrument dataset hosted in the PDS; Chandrayaan-1 was an ISRO mission. Attribute the instrument and mission correctly.

### 5.3 Chandrayaan-1 Mini-SAR / Mini-RF

- **Archive:** [PDS Geosciences Node – Chandrayaan-1](https://pds-geosciences.wustl.edu/missions/chandrayaan1/default.htm)
- **Data:** NASA Mini-RF radar data from Chandrayaan-1, including raw, calibrated, map and mosaic products.
- **Potential use:** Radar-scattering and polar-regolith context.
- **Not suitable for:** Direct elevation or a validated rover hazard mask without further processing and interpretation.

### 5.4 Lunar Prospector – Gamma Ray Spectrometer and Neutron Spectrometer

- **Archive:** [PDS Geosciences Node – Lunar Prospector reduced GRS/NS data](https://pds-geosciences.wustl.edu/missions/lunarp/reduced_grsns.html)
- **Data:** Corrected gamma-ray and neutron spectra and related derived products.
- **Potential use:** Regional elemental-composition and hydrogen-abundance context.
- **Not suitable for:** Local DEM or direct obstacle detection.

### 5.5 LCROSS – Lunar Crater Observation and Sensing Satellite

- **Archive:** [NASA PDS LCROSS Impactor Data Bundle](https://pds.nasa.gov/ds-view/pds/viewBundle.jsp?identifier=urn%3Anasa%3Apds%3Alcross_impactor&version=1.0) · [NASA Open Data catalogue record](https://data.nasa.gov/dataset/lcross-impactor-data-bundle)
- **Data:** Raw, partially processed and calibrated observations collected by the LCROSS Shepherding Spacecraft around the impact into a permanently shadowed lunar region.
- **Potential use:** Scientific background for volatile-bearing polar environments and the LCROSS impact site.
- **Not suitable for:** A general lunar terrain model or direct route planning outside the observation context.

### 5.6 Clementine and other historical lunar orbital data

- **Discovery portal:** [Lunar Orbital Data Explorer](https://ode.rsl.wustl.edu/moon/)
- **Archive index:** [PDS Geosciences Node – Moon exploration holdings](https://pds-geosciences.wustl.edu/dataserv/moon.html)
- **Potential use:** Historical imagery, topography and compositional/contextual products, depending on mission, instrument and collection.
- **Caution:** Product calibration, resolution, coordinate systems and processing levels differ between missions. Inspect each dataset label before combining it with modern LRO layers.

## 6. Recommended dataset stack for LUNA-SAFE

For a credible demonstration, do not download every dataset. Select compatible products for one defined region and explain why each is included.

| Priority | Recommended source | Role in the prototype | Implementation state |
|---|---|---|---|
| 1 | LOLA GDR or SLDEM2015 | Base elevation grid for slope, local relief and terrain-cost analysis | Manual download/import required |
| 2 | LROC NAC DTM (if coverage exists) | Higher-resolution local elevation refinement | Manual download/import required |
| 3 | LROC NAC/WAC image products | Visual comparison and terrain interpretation | Media search is integrated; science-grade map registration is not |
| 4 | Diviner derived products | Thermal-context layer | Not integrated |
| 5 | LEND / Mini-RF | Polar resource and radar context where scientifically appropriate | Not integrated |
| 6 | SPICE kernels | Geometry and illumination/time calculations | Not integrated |
| 7 | CRaTER / DONKI | Radiation and space-weather operational context | DONKI notifications integrated; CRaTER not integrated |
| 8 | M³ / Lunar Prospector / LCROSS / GRAIL | Optional composition, volatile and geophysical context | Not integrated |

**Suggested hackathon demo:** Choose a small named region with both a documented elevation product and an available LROC image/DTM product. Display the dataset name, product ID, coverage, pixel spacing, units, processing level and citation beside the map. Use the real DEM values for slope and route costs. Keep APOD and DONKI in separate panels so the audience can distinguish media/mission context from terrain evidence.

## 7. How to obtain and prepare a real lunar DEM for the current application

### 7.1 Discover a product

1. Define the lunar region of interest and whether it is equatorial or polar.
2. Search [Lunar ODE](https://ode.rsl.wustl.edu/moon/) by mission, instrument, product type and geographic footprint.
3. For LOLA, inspect the [LOLA PDS page](https://pds-geosciences.wustl.edu/missions/lro/lola.htm) and the [LOLA Data Node](https://imbrium.mit.edu/).
4. For SLDEM2015, use the [NASA product page](https://pgda.gsfc.nasa.gov/products/54) and choose a global map or a regional tile matching the area.
5. For LROC, search the [LROC archive](https://pds.lroc.im-ldi.com/data) for matching NAC DTM, NAC image, WAC mosaic or WAC DTM coverage.
6. Download the relevant product label, documentation and data together. Keep the original files unchanged.

### 7.2 Prepare the elevation grid

Before conversion, record and verify:

- Product identifier, archive, version/release and observation/creation dates.
- Coordinate reference system, map projection, central meridian and latitude/longitude direction.
- Pixel spacing in map units and the spatial extent/footprint.
- Elevation sample type, byte order, scale factor, offset and vertical units.
- Elevation reference (for example, the product's stated datum/radius convention).
- Special pixels, fill values and no-data masks.
- Processing level and any calibration or mosaicking history.

Do not assume that a `.IMG`, `.JP2`, `.LBL`, `.XML`, `.TIF` or `.CSV` extension by itself tells you the full data structure. Use the PDS label and the product Software Interface Specification (SIS). Some planetary image files have detached labels and map-projection metadata that a generic image viewer will not understand.

### 7.3 Current LUNA-SAFE upload format and limits

The current endpoint is `POST /api/terrain/upload`.

- It accepts **numeric comma-separated CSV elevation grids only**.
- Grid dimensions must be at least 3 × 3 and no larger than 512 × 512.
- Maximum upload size is 10 MB.
- The endpoint accepts `pixel_spacing` and `vertical_scale` query parameters.
- Input values must be finite; the current importer rejects NaN and infinite values.
- The CSV does **not** retain the source projection, latitude/longitude transform, product ID or vertical datum. The application therefore cannot reliably display real geographic coordinates for this CSV import.
- GeoTIFF, JPEG2000, PDS3 IMG and PDS4 products are **not directly supported** by the current uploader.

Example CSV layout:

```csv
102.4,103.1,104.0,103.8
101.9,102.5,103.6,103.2
100.8,101.7,102.9,102.6
99.9,100.4,101.2,101.8
```

Example upload using `curl` (adjust the path and spacing for your prepared grid):

```bash
curl -X POST \
  "http://127.0.0.1:8000/api/terrain/upload?pixel_spacing=30&vertical_scale=1" \
  -F "file=@lunar_dem_region.csv"
```

`pixel_spacing` is the horizontal distance between adjacent cells. `vertical_scale` multiplies the elevation samples before gradient calculation. For correct slope calculations, the scaled vertical values and horizontal spacing must use consistent units. These values must come from the dataset's label/documentation; do not guess them.

**No-data warning:** Do not replace no-data/fill values with zero. Zero would be interpreted as a real elevation. The current CSV importer rejects non-finite cells, so crop to a contiguous valid region or extend the importer to support a no-data mask before importing a grid with missing cells.

### 7.4 Keep a provenance sidecar

Because CSV loses geospatial metadata, save a sidecar record for every imported grid. A suggested JSON record is:

```json
{
  "display_name": "Lunar DEM – demonstration region",
  "source_mission": "Lunar Reconnaissance Orbiter",
  "instrument": "LOLA",
  "product_type": "GDR",
  "product_id": "FILL_IN_FROM_PRODUCT_LABEL",
  "archive_url": "https://pds-geosciences.wustl.edu/missions/lro/lola.htm",
  "downloaded_at_utc": "YYYY-MM-DDTHH:MM:SSZ",
  "source_file": "original_product_filename",
  "processing_level": "FILL_IN_FROM_LABEL",
  "projection": "FILL_IN_FROM_LABEL",
  "horizontal_spacing": "FILL_IN_WITH_VALUE_AND_UNIT",
  "vertical_units": "FILL_IN_FROM_LABEL",
  "vertical_reference": "FILL_IN_FROM_LABEL",
  "no_data_value": "FILL_IN_FROM_LABEL",
  "conversion_steps": [
    "Read product label",

```

Keep the sidecar and original PDS files alongside the processed CSV in the project's data documentation. Do not commit huge source archives or private API keys to GitHub.

## 8. Processing rules for scientifically responsible terrain analysis

1. **Preserve provenance.** Every real terrain grid must be traceable to a mission, instrument, product ID, archive and version.
2. **Respect map geometry.** Reproject and co-register DEM and imagery before comparing cells. Matching array dimensions alone does not mean that two images cover the same lunar coordinates.
3. **Use physical spacing.** Compute gradients using the map's actual horizontal pixel spacing and elevations with a consistent vertical unit.
4. **Handle no-data correctly.** Maintain a mask. Never convert fill values into real low or high terrain.
5. **Respect coverage and resolution.** A global altimetry DEM and a local NAC DTM have different resolution and coverage. Do not imply that a coarse DEM resolves small rocks.
6. **Separate observations from inference.** A high-slope cell is an elevation-derived estimate. A crater-like depression or boulder-like peak from a grid is a candidate feature until confirmed with suitable imagery or a validated model.
7. **Keep rover thresholds configurable.** The current default slope and roughness thresholds are demonstration assumptions, not certified lunar rover safety limits.
8. **Do not mix unrelated products as if they were one layer.** Thermal, radar, neutron, gravity and composition measurements require separate units, footprints, resolution and interpretation.
9. **Record every transformation.** Keep source grid, processed grid, processing script/version, parameters, resampling method and date.
10. **Make uncertainty visible.** Expose data gaps, resolution, age, uncertainty and source quality in the UI and exported mission report.

## 10. Citation, attribution and reuse

- Cite the specific archive bundle, dataset/product identifier and science-team documentation used—not only the portal homepage.
- For SLDEM2015, include the Barker et al. paper citation and the archive/product version.
- For LROC, LOLA, Diviner, LEND, Mini-RF, CRaTER, M³, GRAIL and other PDS collections, use the citation information in the PDS bundle, product label or instrument archive documentation.
- For images from the NASA Image and Video Library or APOD, preserve item-level credit/copyright metadata and link to the source item. Do not imply that NASA endorses LUNA-SAFE.
- NASA material is not automatically free of every restriction: individual records may contain third-party material, special credit instructions, or separate terms. Read the item-level information before redistribution.
- The LUNA-SAFE source repository does not bundle NASA/PDS terrain archives. A user downloads the dataset from its official archive and imports a supported processed grid.

## 11. Known limitations in this version of LUNA-SAFE

- The default terrain remains procedurally generated synthetic data.
- APOD, NASA Image and Video Library search, and DONKI notifications are live NASA integrations, but none is used as a terrain DEM.
- The project does not automatically query or download LOLA, SLDEM2015, LROC, Diviner, LEND, Mini-RF, CRaTER, LAMP, GRAIL, SPICE, M³, LCROSS or Lunar Prospector products.
- The terrain uploader accepts numeric CSV only; it is not a PDS, GeoTIFF, GeoJP2 or GeoTIFF Cloud Optimized importer.
- CSV import does not preserve map projection, geographic coordinates, source metadata or per-cell no-data masks.
- Terrain hazard detection uses transparent image/elevation-derived rules. It is not a validated lunar boulder/crater detection model.
- Rover energy is a relative estimate, not a validated physical power model.
- No route output is certified for flight or physical rover operation.

### Recommended engineering next steps

1. Implement a geospatial raster importer using Rasterio/GDAL with explicit support for selected LOLA/SLDEM/LROC products and their label metadata.
2. Store CRS, coordinate transform, vertical datum, nodata mask, cell size, product ID and source citation with each terrain layer.
3. Add ODE/PDS product discovery and user-selected download workflows; do not hard-code undocumented endpoints.
4. Co-register LROC imagery with the selected DEM and expose layer resolution/coverage.
5. Add Diviner, radar and neutron layers as independent scientific context, not as unvalidated terrain masks.
6. Validate slope/roughness thresholds against mission-specific rover mobility requirements before presenting any safety claim.
